# План: «Что доесть» — любимые продукты, которыми можно добрать КБЖУ дня


## Контекст

Use case: «Я хочу видеть, что мне нужно съесть, чтобы добрать необходимое КБЖУ на сегодня».
- Новая страница с **любимыми** продуктами в виде матрицы в два столбца.
- Подсвечены продукты, которыми можно добрать калории.
- Не подходящие слегка затемнены: **слишком калорийные** (даже одна порция перебьёт остаток) или **слишком малокалорийные** (пришлось бы съесть нереальное количество).
- Продукты можно отмечать любимыми звёздочкой.

Решения, уточнённые с пользователем:
- Подсказка на **каждой карточке** («≈ 320 г → закроет калории, +40 г белка») плюс сверху **лучший набор** из 1–3 любимых продуктов с граммами и кнопкой «Добавить всё».
- **Тап по карточке** открывает шторку порции с уже подставленными рекомендованными граммами, дальше «Добавить» — запись в дневник, после чего страница пересчитывается.
- **Любимым можно сделать любой продукт** (свой, из Лавки и Пятёрочки, базовый, найденный в OFF). Звёздочка есть в поиске, в «Моих продуктах», в шторке порции и на новой странице.

## 1. Данные и API (backend)

**`backend/prisma/schema.prisma`** — новая связующая таблица. Отдельная таблица, а не поле в `Food`, потому что базовые продукты (`ownerId = null`) общие для всех пользователей:
```prisma
model FavoriteFood {
  userId    Int
  foodId    Int
  createdAt DateTime @default(now())
  user      User @relation(fields: [userId], references: [id], onDelete: Cascade)
  food      Food @relation(fields: [foodId], references: [id], onDelete: Cascade)
  @@id([userId, foodId])
}
```
Плюс обратные связи `favorites FavoriteFood[]` в моделях `User` и `Food`. Изменение только добавляет таблицу: `prisma db push`, предварительно бэкап `dev.db`.

**`backend/src/services/nutrition/foodSearch.ts`**
- `serializeFood(f, favIds?: Set<number>)` добавляет поле `favorite: boolean`.
- Новый хелпер `favoriteIds(userId)` — одним запросом.
- `searchFoods` и `recentFoods` прокидывают набор id любимых в сериализацию.

**`backend/src/routes/nutrition.ts`** (под `nutritionGuard`):
- `GET /nutrition/favorites` — любимые продукты пользователя (полный `Food` с порциями).
- `PUT /nutrition/favorites/:foodId` — продукт должен быть виден пользователю (`visibleTo`), иначе 404. Повторный вызов ничего не ломает.
- `DELETE /nutrition/favorites/:foodId`.
- `GET /foods/mine` и ответы `POST/PATCH /foods` тоже возвращают флаг `favorite`.
- Событие аналитики `food_favorited` через `track()`.

## 2. Логика подбора (frontend, чистые функции)

Новый файл **`frontend/src/utils/suggest.ts`**, без React, чтобы его можно было отдельно прогнать скриптом.

**Остаток на день:**
- `remaining.kcal = plan.todayKcal − totals.kcal`; норма берётся из модели `/nutrition/plan` с учётом тренировочного дня, если плана нет — из цели;
- `remaining.protein = plan.proteinTarget − totals.protein`;
- `remaining.fat` и `remaining.carbs` считаются, только если в цели заданы нормы жиров и углеводов. Отрицательные значения обнуляются.

**Статус каждого любимого продукта.** «Порция» — это первая типовая порция продукта, а если её нет, 100 г.
- `needG = remaining.kcal / kcal100 × 100` — сколько граммов закроет калории.
- **`tooCaloric`:** одна порция больше `remaining.kcal × 1.15`.
- **`tooLight`:** `needG` больше, чем `max(3 порции, 600 г)`, например «3 кг огурцов».
- **`fits`:** всё остальное. Рекомендация — `needG`, округлённые до шага (половина порции, если порция задана, иначе 10 г), с ограничением не больше 3 порций. На карточке показывается, сколько это даст белка.
- **Особый случай:** если `remaining.kcal ≤ 50`, страница показывает «Норма на сегодня закрыта 🎉» и затемняет все карточки.

**Сортировка:** сначала `fits` — по «белку на ккал», если белка осталось добрать больше 10 г, иначе по близости к остатку. Затем `tooLight`, затем `tooCaloric`.

**Лучший набор** (`bestCombo`): перебор сочетаний из 1–3 `fits`-продуктов, у каждого шаги 0–6 по 0,5 порции или 50 г.
- Ошибка = относительное отклонение по ккал, перебор калорий весит в 2 раза больше недобора; плюс относительное отклонение по белку (если осталось больше 10 г); плюс по жирам и углеводам, если они заданы; плюс небольшой штраф за каждый лишний продукт.
- Чтобы перебор был быстрым, берутся только топ-12 `fits`-продуктов: это около 300 тыс. вариантов, в браузере меньше 50 мс.
- Результат: `[{food, grams}]` с итоговыми КБЖУ. Если набор отличается от остатка больше чем на 25%, он не показывается.

## 3. UI (frontend)

- **Новый экран `food-suggest`:** расширить `Screen` в `frontend/src/types/index.ts` и добавить ветку в `App.tsx`; это один из `food-*` экранов, поэтому на него действует флаг доступа.
- **`frontend/src/pages/nutrition/FoodSuggestPage.tsx`** — заголовок «Что доесть», дата `foodDate` из `navStore`:
  - Шапка: «Осталось: 1 240 ккал · Б 46 г · …» (`MacroBars` или компактная строка).
  - Карточка «🍽 Лучший набор»: список «продукт — граммы», итог КБЖУ и кнопка «Добавить всё» (`nutritionStore.addEntries`, приём пищи по времени — `mealByTime`).
  - Сетка `grid grid-cols-2 gap-2` с карточками: название, бренд, ккал на 100 г, звёздочка в углу, подсказка («≈ 320 г / 2 порции», «+40 г белка»). У неподходящих продуктов `opacity-40` и подпись причины: «слишком калорийно» или «мало калорий».
  - По тапу открывается `PortionSheet` с `grams = suggestedG`; `onConfirm` вызывает `addEntry`, затем `loadDay`, и остаток пересчитывается автоматически.
  - Пустое состояние: «Отметь любимые ⭐ в поиске продуктов» и кнопка в `food-add`.
- **Вход на страницу:** третья кнопка «🍽 Что доесть» рядом со «📊 Статистика» и «🎯 Цель и вес» в `FoodDayPage.tsx`.
- **Звёздочка:** новый `components/nutrition/FavoriteStar.tsx` (кнопка ☆/★ с остановкой всплытия клика и haptic). Используется:
  - в `FoodRow` (`FoodAddPage.tsx`) — для поиска, недавних и «Моих продуктов»;
  - в шапке `PortionSheet` — через новое необязательное поле `PortionTarget.foodId` и проп `favorite`/`onToggleFavorite`; при правке записи из дневника (`foodId` есть) звёздочка тоже работает;
  - на карточках новой страницы.
- **Состояние** — `stores/nutritionStore.ts`: `favorites: Food[]`, `loadFavorites()`, `toggleFavorite(food)` с оптимистичным обновлением: поле `favorite` меняется и в `recent`, и в результатах поиска (через колбэк страницы), при ошибке откатывается.
- **API** — `frontend/src/api/nutrition.ts`: `fetchFavorites`, `addFavorite`, `removeFavorite`. В типе `Food` новое поле `favorite: boolean`.

Что переиспользуется: `PortionSheet` и `BottomSheet`, `MacroBars`, `scaleMacros`, `sumMacros`, `fmt`, `mealByTime`, `NUTRITION_COLOR` из `utils/nutrition.ts`, `useBackButton` и `haptic`, `fetchPlan` и `plans` из `nutritionStore`.

## 5. Проверка

- `npx tsc --noEmit` в `backend/` и `frontend/`, затем `vite build`.
- **`utils/suggest.ts`** — прогнать через `tsx` на синтетике: остаток 1200 ккал / 50 г белка, любимые продукты — удон, огурец, майонез, творог, Milky Way:
  - огурец должен получить `tooLight`;
  - майонез при остатке 100 ккал — `tooCaloric`;
  - лучший набор должен попадать в остаток ±25%;
  - при остатке ≤ 50 ккал всё затемнено.
- **API через `fastify.inject`** на тестовом пользователе:
  - `PUT` и `DELETE` `/favorites` повторно ничего не ломают;
  - чужой или невидимый продукт даёт 404;
  - флаг `favorite` приходит в `search`, `recent` и `mine`;
  - удаление продукта каскадно убирает его из избранного.
- **Прод:**
  - `/api/health`, бот запущен;
  - на проде отметить 5–6 любимых продуктов, открыть «Что доесть» в Telegram и проверить подсветку и затемнение, тап с подставленными граммами, «Добавить всё» и пересчёт остатка.
